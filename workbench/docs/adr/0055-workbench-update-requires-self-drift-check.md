# Workbench updates require a Workbench self-drift check

Updating a Workbench includes checking the Workbench itself for semantic drift.
The target project's drift check and the canonical Workbench's self-drift check
are separate operations: the first protects project truth, while the second
protects the artifacts that teach an agent how to start and continue work.

A Workbench update is not complete when a current-facing control, spec,
projection, manifest, procedure, or managed artifact still says that completed
work is pending, names a resolved blocker, points at a retired route, or carries
stale version/provenance information that can misroute a cold-start agent.
Historical evidence may retain old claims when its time, source, and status are
explicitly bounded; preserving history is not permission to expose it as
current state.

The self-drift check inventories the steering and operational artifacts needed
for a cold start: root controls and their generated projections, the manifest,
current and planned Specs plus the catalog, active ADRs and their register, the
Wiki router, update and review procedures, templates, managed tools and skill
receipts, seeded contract documents, and readable continuity-record metadata.
It classifies findings as current, historical, planned, blocked, stale,
contradictory, or unreadable and names the owning correction. A structural
`render`, `doctor`, or passing test is useful evidence but does not establish
semantic freshness by itself.

Considered alternatives: Checking only the target project misses stale source
guidance in the Workbench being distributed. Checking only generated bytes lets
the renderer faithfully project an already-stale spec. Treating all old claims
as errors would destroy useful history and corrections. A manual review without
a durable owner would repeat the same omission on the next update.

Consequences: S-00K owns the public check, its blocking semantics, repair route,
and cold-start proof. `update-harness` and the root/template Runbooks must run
the Workbench self-drift check before and after a canonical Workbench update;
until S-00K is implemented, the update records a bounded manual check and may
not claim a clean Workbench update while known current-facing drift remains.
Existing stale records are preserved until their owning lifecycle disposition
is reconciled. The check does not authorize publication, downstream rollout,
or deletion of historical evidence.

Provenance: owner-requested Workbench self-drift correction, 2026-09-10; live
drift review at `c0ac60a179235ef22fa6ea81aec74735087e06e5`. The review found
v3.1-era blocked release records still projected beside the v3.2.0 manifest,
five v3.1.4-seeded artifacts, a v3.1.0 provenance mismatch, and unreadable
legacy continuity records. Acceptance of this decision is not a claim that the
checker or the repairs are implemented.
