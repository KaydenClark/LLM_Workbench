# A release is proven by the Template building a real product in one pass

Landmark: Workbench Template.

1. Among its other gates, a Workbench release is proven when the Template, updated to that release and deployed in the cloud, is run through a grilling session from a prewritten grill-me-and-genesis script and produces the website asked for, correctly, without being blocked by anything that should not block it. It must take the workflow in a single pass (Idea, Align, Confirm, Journey, Complete) with no second Align; the owner's only step is Approve, judging whether the website is viable.

2. The release proof builds Puffer Pond (github.com/KaydenClark/Puffer-Pond), the small full-screen living pond illustration, from the prewritten grilling script, with the Template deployed in the cloud.

Why the owner chose it:

- The owner, in his own words (2026-10-03, teardown round 1): "The idea is the workbench can take a do the workflow in a single pass ... without a second align needed. It theorectically should just be the human QA step."
- The owner (teardown round 1): "when I can effortless algin my design concepts into products, where I Align confirm. and come back to a finished product to approve"
- For the Puffer Pond choice, the owner's confirmed reason: A website is a product the owner can judge viable by using it, so Approve stays the owner's only step, and running it in the cloud from a script proves the pass needs nothing from the owner's machine or memory.

Considered and rejected: None recorded.

Consequences: None recorded as owner words. The workflow list is recorded as locked; the terms-and-verbs work may rename a verb, and a visible correction here would then be needed, not a silent edit. How this proof relates to the existing Template upgrade release gate is the release-proof Spec's to state.
