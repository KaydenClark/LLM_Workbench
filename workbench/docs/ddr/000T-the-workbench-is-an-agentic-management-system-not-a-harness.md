# The workbench is an agentic management system, not a harness

Landmark: none, Blueprint level.

The owner, in his own words (chat, 2026-10-03): "Room has always meant project. What is inaccurate about what was written and needed correction was Claude code and codex already have harnesses. What we are building is an agentic management system. So a workbench is NOT the operating harness. The workbench is an agentic management system claude code and codex uses to align my ideas and implement my design concepts. Harness should mean the same thing it always has."

Why the owner chose it:

- The owner's reason, in his own words (round 4): Claude Code and Codex already have harnesses. What we are building is an agentic management system: the one Claude Code and Codex use to align my ideas and implement my design concepts.
- The owner (2026-10-02, teardown round 1): "The Harness is more the codex and claude code desktop apps. This is how I am managing the agents who are using that harness."
- The owner (teardown round 1): "within a single project, I should only need to interveen when I am aligning or unblocking items"

Considered and rejected: Calling the workbench the operating harness, which the Lexicon Workbench row and the Blueprint's first paragraph said. The owner: "a workbench is NOT the operating harness."

Consequences: The lock records these as promotion consequences, not as this decision: the Lexicon Workbench row, a Harness row, the retirement of "operating harness" as a name for the Workbench, and the uses of "harness" for the workbench elsewhere in the repository, which are to be dispositioned at promotion by the terms work. Stated as fact: [Evidence for claims of improved agent outcomes](../adr/0044-evidence-for-claims-of-improved-agent-outcomes.md) and [Unavailable baseline for a bounded harness-only change](../adr/0049-unavailable-baseline-for-a-bounded-harness-only-change.md) use "harness" for the Workbench itself; this record does not disposition them.
